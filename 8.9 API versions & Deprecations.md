# API versions

El versionamiento de APIs en Kubernetes es lo que permite que el sistema evolucione sin romper los manifests ni las aplicaciones. Es una de las claves para mantener compatibilidad hacia atrás mientras se introducen mejoras.

Cada recurso en Kubernetes tiene un campo:

```sh
apiVersion: <grupo>/<versión>
```

Ejemplo:

```sh
apiVersion: apps/v1
kind: Deployment
```

Esa versión (v1) indica qué “madurez” y estabilidad tiene la API.

## Tipos de versiones en Kubernetes

Kubernetes usa 3 niveles principales:

### Alpha (v1alpha1, v2alpha1…)

- Muy experimental
- Puede cambiar o desaparecer sin aviso
- Deshabilitada por defecto en muchos clusters

Ejemplo:

```sh
apiVersion: networking.k8s.io/v1alpha1
```
### Beta (v1beta1, v2beta1…)

- Más estable, pero aún puede cambiar
- Bastante usada en el pasado
- Puede ser deprecada

Ejemplo clásico:

```sh
apiVersion: apps/v1beta1 
```

###  Stable / GA (v1, v2…)

- Estable (General Availability)
- Compatible hacia atrás
- Recomendado para producción

```sh
apiVersion: apps/v1
```

**¿Cómo evoluciona una API**

alpha → beta → stable (GA)
