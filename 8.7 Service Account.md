# Service Account

Los Service Accounts en Kubernetes son identidades que usan los pods (y sus contenedores) para interactuar con el API Server de Kubernetes de forma segura.

**¿Cómo funciona internamente?**

1. Creación del ServiceAccount

Cuando creas un ServiceAccount, Kubernetes genera una identidad dentro de un namespace.

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: mi-app-sa
  namespace: default
```

2. Asociación con un Pod

Un pod puede usar ese ServiceAccount así:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: mi-pod
spec:
  serviceAccountName: mi-app-sa
  containers:
  - name: app
    image: nginx
```

3. Token automático (lo importante)

Cuando el pod arranca, Kubernetes hace esto automáticamente:

- Genera un token JWT
- Lo monta dentro del contenedor como archivo:
```sh
/var/run/secrets/kubernetes.io/serviceaccount/token
```

También monta:

- CA del cluster
- namespace

4. El Pod usa ese token

Dentro del contenedor, tu aplicación puede usar ese token para hacer requests al API Server:

Ejemplo:

```sh
curl https://kubernetes.default.svc \
  --header "Authorization: Bearer $TOKEN"
```

5. Autorización (RBAC entra en juego)

El token solo identifica quién eres.
Lo que puedes hacer depende de:

- Role / ClusterRole
- RoleBinding / ClusterRoleBinding

Ejemplo:

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: leer-pods
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list"]
```

```yaml
kind: RoleBinding
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: bind-leer-pods
subjects:
- kind: ServiceAccount
  name: mi-app-sa
roleRef:
  kind: Role
  name: leer-pods
  apiGroup: rbac.authorization.k8s.io
```

Flujo completo

1. El pod usa un ServiceAccount
2. Kubernetes le inyecta un token
3. El pod llama al API Server con ese token
4. El API Server:
    - Autentica (¿quién eres?)
    - Autoriza (¿qué puedes hacer?) usando RBAC

Nota:

- Si no defines un service account, Kubernetes usa uno llamado: default
- Desactivar automount si no lo necesitas:

```sh
automountServiceAccountToken: false
```
