# Custom Resource Definition

Los Custom Resource Definitions (CRD) son el mecanismo que te permite extender Kubernetes con tus propios tipos de recursos, integrados directamente en el API como si fueran nativos.

**¿Cómo funciona internamente?**

1. Registras el nuevo tipo (CRD)

Creas un objeto CustomResourceDefinition que define:

- Group → dominio lógico (miempresa.com)
- Version → (v1, v2)
- Kind → tipo (Database)
- Plural → (databases)
- Schema → cómo debe ser el objeto (validación)

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition
metadata:
  name: databases.miempresa.com
spec:
  group: miempresa.com
  names:
    kind: Database
    plural: databases
  scope: Namespaced
  versions:
  - name: v1
    served: true
    storage: true
    schema:
      openAPIV3Schema:
        type: object
        properties:
          spec:
            type: object
            properties:
              engine:
                type: string
              version:
                type: string
```

2. Kubernetes lo agrega a su API

Después de aplicar el CRD:

```sh
kubectl get databases
```

3. Creas instancias del recurso

```yaml
apiVersion: miempresa.com/v1
kind: Database
metadata:
  name: mi-db
spec:
  engine: postgres
  version: "15"
```

**¿Dónde vive este recurso?**

Se guarda en etcd
- Pasa por:
    - autenticación
    - autorización (RBAC)
    - admission controllers

Es un recurso “real” dentro del cluster.

¿Hace algo automáticamente? No por sí solo, para esto necesitamos Controllers / Operators

## Controllers / Operators

Para que un Custom Resource tenga comportamiento necesitas un controller:

- Observa los recursos Database
- Ejecuta acciones automáticamente

Ejemplo:

- Crear un Pod con Postgres
- Crear un PVC
- Exponer un Service

Este patrón se conoce como Operator.

**Flujo completo**

```sh
Creas CRD
   ↓
Creas recurso (Database)
   ↓
Se guarda en etcd
   ↓
Controller lo detecta
   ↓
Ejecuta acciones (crear pods, etc.)
```

Ejemplos reales

Muchas herramientas usan CRDs:

- Istio → define recursos como VirtualService
- Cert-Manager → define Certificate
- Argo CD → define Application
