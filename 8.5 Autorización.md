# Autorización

La autorización en Kubernetes (K8s) es el proceso de seguridad que determina qué acciones (verbos como get, create, delete) pueden realizar los usuarios o servicios autenticados sobre recursos específicos (como pods o deployments) dentro del clúster. 

Cuando haces una request al API Server:

Autenticación → Autorización → Admission Controllers

1. Autenticación → quién eres
2. Autorización → qué puedes hacer
3. Admission → reglas adicionales (validaciones/mutaciones)

**¿Qué evalúa la autorización?**

Cada request se evalúa con estos atributos:

- Usuario / ServiceAccount
- Recurso (pods, deployments, etc.)
- Namespace (si aplica)
- Verbo (get, list, create, delete, etc.)
- API Group

Ejemplo mental:

¿El usuario "juan" puede hacer "delete" sobre "pods" en "default"?

## Módulos de autorización (Authorization Modes)

### 1. RBAC (Role-Based Access Control)

Define permisos usando:

- Roles / RoleBindings
- ClusterRoles / ClusterRoleBindings

Rol que permite leer pods
```
kind: Role
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  namespace: default
  name: pod-reader
rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list"]
```

Asignar el rol a un usuario
```
kind: RoleBinding
apiVersion: rbac.authorization.k8s.io/v1
metadata:
  name: read-pods
  namespace: default
subjects:
- kind: User
  name: juan
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

**Resultado:**
juan puede leer pods en default, pero no borrarlos
